# NeuroEphys AI 文件存储与迁移规范

## 1. 唯一正式工作区

正式工作区根目录命名为 `codex_neuroephys_ai`。它必须使用真实文件，不得用快捷方式、目录联接或符号链接代替 App、源码、样例数据和结果。

根目录固定包含：

1. `00_START_HERE`：首次使用说明；
2. `01_Application`：Full 便携 App 与安装包；
3. `02_Source_Code`：干净的 Git 仓库、完整历史 bundle 和必要的恢复资料；
4. `03_Example_Projects`：可直接打开的完整样例和教学样例；
5. `04_User_Projects`：用户新项目的推荐位置；
6. `05_Research_Data_Catalog`：不随工作区复制的真实数据目录清单；
7. `06_Documentation`：用户、科研方法、开发和交接文档；
8. `07_Validation_and_Results`：版本验收、科研验证和论文复现证据；
9. `08_Manifests_and_Recovery`：清单、校验值、路径修复和迁移报告。

## 2. 新电脑迁移规则

必须复制整个根目录，不能只取 App 或某个 session。复制后先运行根目录的 `START_NEUROEPHYS_AI.cmd`，由脚本重新绑定项目内部的相对数据路径，再从 App 导入 `03_Example_Projects` 下的项目。

## 3. 真实数据边界

真实原始实验数据应保持只读并与可公开样例分开。它们不放进安装包，也不为了“看起来完整”而重复复制。清单必须写明数据名称、绝对位置、大小、是否纳入工作区以及未纳入原因。

## 4. 可清理内容

以下内容在确认已归档后可以移入隔离区并最终删除：旧虚拟环境、构建缓存、旧安装包副本、被新 Git 仓库取代的工作树、重复验证输出和旧索引式归档。删除前必须先保存未提交补丁、Git 历史、科研结论和必要验证证据。

## 5. 每次更新后的维护

发布或重大数据更新后，应同步更新 GitHub、完整 Git bundle、文件清单、关键文件哈希、外部数据目录表和迁移验证报告。正式工作区与 E 盘安全副本应保持相同结构。
