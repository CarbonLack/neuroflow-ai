## 一 项目介绍

### 项目定位

NeuroEphys AI 是面向在体细胞外多通道电生理研究的本地优先分析平台。第一阶段明确服务于 extracellular electrophysiology，包括宽带或高通记录、spike、candidate unit、TTL、行为事件、trial、群体神经活动，以及数据确实包含低频成分时的 LFP。平台不把膜片钳、EEG、fMRI 或钙成像包装成已经支持的能力，也不把候选簇自动等同于经过专家确认的单神经元。

项目面向需要处理真实实验数据的神经科学研究人员、研究生、实验室数据管理员和需要复核分析结果的合作者。它既提供 Windows 桌面应用，也提供可脚本化的 Python 包，使初学者能够按步骤完成分析，使熟练用户能够保留完整参数、切换算法、导入外部结果并进行批处理。

### 需要解决的问题

在体电生理分析通常横跨记录系统、二进制格式、探针信息、Python 或 MATLAB 环境、CUDA、多个 spike sorter、行为学程序、TTL 时钟、统计软件和科研作图工具。成熟开源项目已经提供许多可靠算法，但研究人员仍需自行解决接口不一致、依赖冲突、参数重复录入、结果散落、失败任务难以恢复、人工决定缺乏记录，以及 Methods 和图表需要重新整理等问题。

这一问题对初学者尤其明显。研究人员即使能够运行某段代码，也未必知道某个参数为什么这样设置、当前图表示什么、统计单位是 trial、unit、session 还是 animal，以及某个显著结果能否支持生物学结论。长时原始电压、视频和未发表行为数据体积大且敏感，也不适合依赖全部上传云端的分析模式。

### 数据入口和项目管理

平台支持通用交错通道二进制文件，以及 Open Ephys、Intan、SpikeGLX、Blackrock、Plexon、TDT 和 NWB 等记录系统入口；还可以导入 IBL ALF、Kilosort/Phy 结果和 NeuroExplorer/Offline Sorter 的 NEX5 候选 Unit。记录系统通过 SpikeInterface 等公开接口只读访问，缺少原始电压时会明确跳过原始质控和重新 sorting，不会伪造结果。

每个项目保存来源索引、元数据、参数、日志、中间结果、sorter 原生输出、统一结果、图表和导出文件。原始数据保持只读，分析文件进入独立项目目录。用户关闭软件后可重新打开 `neuroflow_project.json`，恢复当前阶段、参数、运行记录、人工复核状态和 AI 对话。失败任务不会删除此前已经完成的结果。

### 单 Session 分析流程

桌面工作台把分析组织为十一阶段：数据与项目、原始质控、预处理、spike sorting、Unit 质量和人工复核、事件同步、行为分析、神经活动、统计检验、机器学习以及论文与复现。每个阶段说明输入、输出、参数、适用条件和科学限制，用户可以跳过不适用于当前数据的节点，也可以替换 sorter、统计方法和绘图方案。

原始质控包括波形浏览、通道 RMS、坏通道、饱和和线路噪声检查。预处理提供高通或带通以及 common median reference 等预览。软件不会在采集阶段已经滤除低频成分的数据上强行生成 LFP 结论。波形浏览可以调整时间起点、窗口、通道范围、可见通道数和增益，便于检查长记录中的局部异常。

### Spike sorting 和 Unit 复核

平台明确适配和探测 Kilosort4、MountainSort5、SpyKING CIRCUS 2、Tridesclous2、Simple 和 Lupin 六种方案。每次运行保存 sorter 名称、版本、参数、日志、原生文件和结果目录，并转换为统一的 Unit 到秒级 spike time 接口。不同 sorter 的结果不会相互覆盖，用户可以切换当前结果，并查看候选 Unit 数、spike 数、配对 Unit、各自特有 Unit 和时间戳一致度。

模拟数据存在 ground truth 时，平台可以报告 precision、recall、F1、miss rate 等检测性能。真实数据没有 ground truth 时，只报告算法间一致度，不能把 agreement 称为 accuracy，也不能因为某个 sorter 产生更多簇就宣称它更好。Unit 质量模块计算发放率、ISI violation、波形、SNR、漂移或稳定性等证据，并允许研究者记录 candidate single unit、multi-unit activity、noise 或 uncertain。自动筛选只产生候选暂留结果，最终标签仍需专家结合波形、不应期、漂移、重复和合并拆分风险人工确认。

### 行为同步和神经活动分析

行为数据可以包含 trial、condition、event type、choice、outcome、reaction time、位置、速度和 lick 等字段。行为设备与电生理采集卡分别记录同步脉冲时，平台按顺序配对并拟合电生理时间等于 offset 加 slope 乘以行为时间，保存脉冲数、漂移和全局残差。它不会把用于拟合的锚点插值残差误当成独立验证误差。

完成同步后可以生成 raster、PSTH、群体热图、单 trial 活动、细时间分辨 population、PCA 排序和群体轨迹。Neo 和 Elephant 相关功能用于放电统计、CCH、STTC、spike-train 距离和连接性分析；只有存在真实低频信号时才开展频谱、相干性、spike-field phase locking 和相位耦合分析。

### 统计 机器学习和多 Session 研究

统计模块支持参数和非参数检验、置换、bootstrap、效应量、多重比较校正和混合模型。报告需要说明有效样本量和数据层级，不能把 Unit 数量当作动物重复。机器学习模块提供分类、连续变量回归、交叉验证、置换、ROC、F1、特征重要性、K-means、GMM、时间分辨解码、心理测量曲线和群体 PCA 轨迹。

一个普通项目对应一个 recording session。Study 层把多个已经完成的项目只读索引为多 Session 或多动物研究，显式保存 animal、session、条件和纳入状态。用户可以选择 Logistic、线性或 RBF SVM、收缩 LDA 和随机森林，并按整只动物或整个 Session 留出。标准化只在训练折拟合，输出逐留出组性能、混淆矩阵、分组置换和 bootstrap 区间。只有一只动物时自动退回按 Session 留出，并禁止表述为跨动物泛化。不同 Session 中相同 Unit ID 不会被默认视为同一细胞。

### 科研作图和论文导出

Figure Studio 支持按整图、子图、坐标轴、曲线、散点、柱形或填充区、热图、文字和图例编辑。用户可以对单个对象、当前子图、当前整图或项目全部图应用样式，并保存项目统一标准。默认分类色使用低饱和浅紫、柔绿、浅赭和灰蓝，支持可编辑 SVG 与 600 DPI PNG，提供单栏和双栏尺寸参考。

论文模块把实际生成的英文结果图按数据质量与实验设计、单 Unit 响应、群体结果、统计或解码、稳健性证据组织为主图和附图。每张图进入主图、附图或源数据清单，生成 panel 字母、英文图注草稿、Methods、统计表和 provenance。该模块提供可审核草稿，不宣称自动完成目标期刊的最终技术审查。

### 当前验证和预期效果

两类 20 分钟 ground-truth 模拟 session 已从原始二进制重新建立项目、单独导入行为数据，并运行 Kilosort4、MountainSort5 和 SpyKING CIRCUS 2，保存原生结果、统一结果、ground-truth 评估、比较、下游图和出版草稿。五只真实动物已完成 15 个动物乘 sorter 工程链路，包括导入、参数、日志、候选簇、自动筛选、行为同步、事件分析和英文导出。IBL、Buzsaki Lab DANDI 和 Trautmann 公开数据用于验证数据入口、统一结构和部分方法一致性。

平台预期减少环境配置、格式转换、重复参数录入和手工整理 Methods 的时间，提高异常发现、分析复核、实验室交接和结果复现的完整度。现阶段可以用已通过的工作流、测试和项目证据证明功能可运行，但尚未用大规模用户研究给出统一的节省时间百分比。正式增效将以任务完成时间、失败次数、参数遗漏、结果复核一致性和项目复现成功率进行测量。

## 二 AI 应用情况

### AI 在产品中的职责

NeuroEphys AI 采用 AI 解释与规划、本地确定性模块计算的分工。数据导入、质控、sorting、同步、统计、机器学习和绘图由本地注册模块执行。AI 负责解释当前页面和结果、检查流程缺口、提出候选工作流、说明匿名化错误、检索项目内历史对话，并在协作模式下提出受控工具调用。这样可以利用语言模型的理解和交互能力，同时避免让模型直接替代数值计算或绕过科研流程。

### 模型和 Provider 接入

机构提供的模型权限需要运行在官方支持的 DeepSeek Harness 中，因此 App 使用 Harness SDK 读取非敏感配置并完成身份认证和模型请求，不复制 Harness 的模型密钥，也不绕过机构规定直接访问接口。Provider 层与分析代码分离，同时保留兼容实验室私有服务、本地模型和其他 OpenAI-compatible 端点的能力。AI 服务断开、未配置或关闭时，全部手动分析功能仍可运行。

### 项目上下文和对话记忆

应用使用有版本号的结构化项目上下文协议。每次请求自动加入当前项目、当前节点、已完成、失败或跳过的步骤、参数、结果摘要和界面位置。经用户授权后，AI 可以按需查询指定 Unit 的质量指标和 spike time、特定事件、trial、结果表、日志和项目内历史对话。对话保存在当前项目的 `ai/conversation.json` 中，重新打开项目后可以继续；不同项目默认隔离。

AI 可以读取图标题、坐标范围和结构化结果，但不能据此声称已经看见图像像素。新分析模块必须先把结构化结果注册到项目摘要，AI 才能理解；新操作还必须加入工具白名单和参数 Schema，理解功能并不自动获得执行权限。

### 三种工作模式

手动模式不向模型发送请求，所有节点由用户选择和运行。助手模式允许解释项目、参数、结果和错误，也可以提出候选流程，但不会执行工具调用。协作模式允许模型提出白名单工具调用，本地程序检查工具名称、参数、前置节点、输入和风险，随后显示确认窗口。Sorting、覆盖结果、批量处理、长时间任务和任何在线发送都要求用户确认。

右侧 AI 面板默认使用简洁阅读模式，先显示结论、最多三个关键点、已查证据、待确认操作、下一步和重要警告。详细科学解释、限制、证据编号和候选操作可以展开查看。完整回答仍写入项目记录，因此界面压缩不会降低审计能力。

### AI 参与的开发环节

AI 参与了需求拆解、源代码实现、界面迭代、自动测试、错误诊断、文档生成、数据适配、结果说明和发布检查。每项完成声明都需要对应代码、测试、项目输出、图表、日志或安装包验收，不能把模型回复本身当作完成证据。AI 也协助维护项目交接文档和 living archive，使后续项目经理可以恢复源码版本、Git 历史、发布证据和大型数据的位置。

### 数据安全和合规

原始电压、视频和完整行为文件默认留在本机。在线模型只接收用户预览并授权的最小结构化摘要，本机绝对路径、身份字段、原始数组和 API 密钥在请求前剥离。密钥仅保存在运行内存、环境变量或操作系统凭据区，不写入项目、日志、报告或 Git 仓库。每次请求记录 Provider、模型、发送字段类别、用途、授权和状态。

模型没有任意文件系统、任意 Python 或未注册工具的权限。删除原始数据、覆盖结果和未经授权的数据传输不在白名单中。候选 cluster、AI 解释、统计结果和论文图均需研究者结合实验设计复核。公开演示材料使用模拟数据、合规公开数据或脱敏工程摘要。

### AI 接入验证

当前开发机已验证 Harness 非敏感配置识别、模型列表读取、最小真实请求、紧凑工具建议转换和 `inspect_project` 白名单参数校验。测试没有自动执行 AI 建议的分析操作，原始电压、本地路径和密钥没有进入请求。应用还通过回归测试覆盖上下文生成、权限校验、简洁阅读和完整依据切换。

## 三 作品开发进度

### 当前交付状态

当前正式版本为 v1.3.1。项目已经形成 Windows 标准安装版、标准便携版、可选择 GPU/CUDA/Kilosort 组件的 Full 安装版、Python wheel 和源码包。普通用户安装后可从桌面启动，不需要另外安装 Python 或 Conda；脚本用户可以通过 `neuroephys-ai` 包调用公开 API 和命令行。项目同时提供中文和英文 GitHub 教程、网页手册、内置教程中心、发布说明和数据安全说明。

### 已完成的主要功能

已完成数据导入和项目恢复、原始质控、预处理预览、多 sorter 运行与统一比较、Unit QC 与人工标记、TTL 和行为同步、行为及事件分析、神经活动图、统计和机器学习、Figure Studio、Methods 与 provenance 导出、英文主图和附图草稿，以及受控 AI 助手。Study 层已经支持多个 Session 和多个动物的条件汇总、分组交叉验证、置换、bootstrap、混淆矩阵和描述性群体动力学。

已适配的六项 sorter 为 Kilosort4、MountainSort5、SpyKING CIRCUS 2、Tridesclous2、Simple 和 Lupin。完整安装分支和仅通用核心分支分别经过独立安装验证，取消 GPU 组件时不会留下不完整的 Torch 模块。

### 测试和发布证据

当前源码完整测试结果为 169 passed。中文和英文 Sphinx 文档均以 warning-as-error 模式构建通过。Full 独立打包目录和全新安装目录通过启动、AI 安全桥、SVG/PDF/PNG 导出、MountainSort5、内置 sorter 集合和 Kilosort4 六项自检。可选安装的通用核心和完整 GPU/Kilosort 两条路径也分别验收。

GitHub 已公开源码、安装教程和 v1.3.1 Release；中英文教程网站可在线访问。Full 安装器保存在云端 Release，本地同时保留完整便携归档和校验值。项目 living archive 保存当前源码 ZIP、完整 Git bundle、发布和验证文档，并在 Git 提交、切换、合并和打包后自动刷新。

### 科研验证状态

两类 20 分钟模拟 session 已完成三 sorter 和下游流程验证。真实数据方面，101、102、104、105、108 五只动物均已完成 Kilosort4、MountainSort5 和 SpyKING CIRCUS 2，共 15 个动物乘 sorter 项目。行为同步、事件分析、英文导出和图形完整性审计已有结果。12 点记录的 33 到 64 通道没有对应动物和行为，因此可以保留纯电生理 sorting，但不会纳入动物行为结论。

这些结果证明工程流程可以运行，不代表所有候选 Unit 已被人工确认为 single unit，也不代表所有实验设计具有足够统计功效。真实数据的 sorter 间一致度不能当作 ground-truth accuracy，自动筛选通过数量也不能替代专家复核。

### 尚需完成的工作

第一，完成真实候选 Unit 的波形、不应期、漂移、存在性、重复、串扰和合并拆分人工复核，并由数据提供者确认动物映射和行为语义。第二，基于人工确认结果刷新正式事件统计、跨动物模型和最终图板，同时保留零结果和反例。第三，邀请未参与开发的新用户完成导入、分析、保存、恢复和导出任务，量化学习成本、错误率和时间。第四，在更多 Windows 硬件、显卡、驱动和无开发环境电脑上进行冷机安装测试。第五，根据目标期刊要求完成最终图形尺寸、字体、色盲、灰度、图注和统计报告审查。

### 决赛前安排

决赛前冻结演示版本和示例项目，检查 Full 与标准安装包、桌面快捷方式、账号、网络、Harness 登录、模型服务和本地缓存。准备一条不依赖现场网络的完整手动分析路径，并录制从导入数据、运行节点、查看 AI 解释、编辑图形到导出结果的备用视频。现场演示以实际问题、解决流程、AI 的具体职责和验证证据为主，不为了演示时长删除正式产品功能，也不增加与科研工作流无关的功能。
