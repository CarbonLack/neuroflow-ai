Parameter reference

Defaults are starting points, not universal truth. Change one setting at a time, preserve the reason, and compare evidence before and after.

01 Start with the data structure

ParameterMeaningDefaultRecommendationEffect of changing it
Sampling rateSamples per second; converts sample indices to seconds.Simulation: 30,000 Hz; device files: read from metadataUse the acquisition value exactly; extracellular spike recordings commonly use 20–30 kHz.A low value stretches time and lowers frequencies; a high value compresses time and raises frequencies.
Channel countAll channels stored per time point, including auxiliary channels in the file.Defined by the simulation electrode templateUse the number physically written to the file, not merely the channels selected for sorting.A wrong value reshapes the file and often creates repeated, shifted, or diagonal patterns.
dtypeStorage type of each sample on disk.int16Read it from device metadata or export settings; never interpret float32 as int16.A wrong dtype changes frame length and numeric interpretation; the file may open with invalid traces.
µV / bitMicrovolts represented by one integer ADC step.Generic import: 0.195; device import: read or normalizeUse the acquisition gain; if unknown, keep ADC counts and mark units as unknown.Affects amplitude units and amplitude-dependent thresholds, not spike sample locations.
Copy sourceChooses a read-only link or a copied raw binary inside the project.Off: read-only linkUse a link for stable storage; copy when the project must move or be archived independently.Copying improves portability at a storage cost; links save space but fail if the source moves.

02 Raw-signal quality control

ParameterMeaningDefaultRecommendationEffect of changing it
Time startStart of the displayed recording window.0 sInspect the beginning, middle, end, and intervals around key task events.Changes the view and local metrics without cropping the source.
WindowDuration displayed at once.60 msUse 20–100 ms for spikes and 1–10 s for slow artifacts or rhythms.Short windows reveal waveforms; long windows reveal trends but compress spikes.
Channel rangeFirst channel and number shown together.Ch 0–11Inspect 8–16 channels at a time on dense probes and move along depth.Too many channels reduce readability; too few can hide spatially shared patterns.
Display gainVertical display multiplier only.1.0×Start at 1.0×, decrease for overlap, and increase for small traces.Does not alter data or QC values; it only changes the view.
Line frequencyCenter frequency for narrowband mains-power measurement.50 Hz in China and most regionsChoose 50 or 60 Hz for the recording location and inspect harmonics.The wrong choice misses mains noise but does not alter the source.

03 Preprocessing is not a fixed recipe

ParameterMeaningDefaultRecommendationEffect of changing it
AP bandPassband used for spike detection or preview.300–6000 HzStart with sorter/domain defaults and adjust only from sampling rate and spectral evidence.A high lower cutoff suppresses broad spikes; a low one retains LFP drift. The upper cutoff must stay below Nyquist.
LFP low-passHighest retained LFP frequency.300 HzUse 150–250 Hz for analyses below 100 Hz; retain a higher cutoff and sampling rate for high-frequency oscillations.Lower cutoffs smooth transients; overly high cutoffs allow spike leakage into LFP.
LFP sampling rateSamples per second retained after LFP filtering.1,000 HzKeep at least twice the highest target frequency; 4–10× margin is common.Too low causes aliasing or poor phase precision; too high increases memory and computation.
ReferenceCommon reference estimate subtracted from each channel.Common medianStart with median for dense recordings; use probe groups and reference design for sparse tetrodes or microwires.Average is more sensitive to outliers; median is robust, but both can remove genuine common activity.
NotchSuppresses 50/60 Hz and optional harmonics.OffEnable only when QC shows narrowband contamination that cannot be corrected at acquisition.Notching changes amplitude and phase around the target and can affect coupling analyses.

04 Spike sorting and tool selection

ParameterMeaningDefaultRecommendationEffect of changing it
SorterSpike-sorting backend that will actually run.Kilosort4Evaluate Kilosort4 first for dense Neuropixels; compare CPU sorters for sparse/tetrode recordings.Sorters differ in preprocessing, detection, clustering, and resources; they are not interchangeable parameter presets.
n_chan_binTotal channels in the Kilosort binary, including channels not used for sorting.Read from the project structureMust match the physical file layout; Neuropixels 1.0 files commonly contain 385 channels.A wrong value creates diagonal/repeated heatmaps and should stop the run immediately.
batch_sizeSamples processed in each Kilosort batch.60,000 (2 s at 30 kHz)Start with the default; for ≤64 channels, a longer batch can improve drift estimation.Larger batches need more memory; short batches contain fewer spikes for drift estimation.
nblocksNumber of depth blocks used for drift correction.1 (rigid drift)Start at 1 for a single-shank Neuropixels probe, try 5 for non-rigid drift, and consider 0 for ≤64 sparse channels around ≥50 µm spacing.Zero disables correction; too many blocks make sparse estimates unstable.
Th_universal / Th_learnedDetection thresholds for universal and learned templates.Current Kilosort4 defaultStart with defaults; lower by only 1–2 at a time when spikes are missed or units disappear.Lower thresholds detect more events but increase noise and computation.
tmin / tmaxStart and end times included in sorting.Full recordingCrop only confirmed start/end artifacts and document the exclusion.Short ranges speed testing but cannot establish full-session stability.
duplicate_spike_msWindow for removing near-duplicate spikes within a unit.Kilosort4 defaultAdjust only for a supported duplicate peak around zero in the ACG; never exceed 0.5 ms.Large values corrupt refractory-period and ACG/CCG estimates.

05 Unit QC and manual review

ParameterMeaningDefaultRecommendationEffect of changing it
Firing rateSpikes per second over valid recording time.Report only; no automatic exclusionInterpret with brain region, cell type, duration, and stability.A higher minimum removes sparse units but can discard real low-rate cells.
ISI violation windowWindow used to count refractory-period violations.2 msStart around 1–2 ms and report the exact definition.Larger windows count more violations; values are incomparable without the definition.
SNRWaveform signal magnitude relative to background noise.Report onlyUse one method consistently and inspect waveforms; do not transfer thresholds blindly across tools.Higher thresholds are conservative but penalize real low-amplitude units.
Amplitude stabilityChange in spike amplitude over time.Full-session timelineLook for decay, jumps, or brief presence and compare with drift diagnostics.Overly strict criteria reject real state changes; loose criteria retain drifting or disappearing units.
Contamination thresholdAllowed estimated contamination.Not treated as ground truthIf 10% is shown as a guide, report the estimator and review it with ACG and waveforms.Lower thresholds reduce unit count and increase conservatism, but the estimate is itself uncertain.

06 TTL, behavior, and a common timeline

ParameterMeaningDefaultRecommendationEffect of changing it
Behavior time columnColumn containing behavior-device timestamps.time_secondsConvert to seconds while retaining the source column; frame indices require frame rate or per-frame timestamps.A unit mistake creates 1000× or sampling-rate-scale errors.
TTL pairingHow behavior and ephys pulses are paired.Pair one-to-one in orderCheck counts and intervals first; locate missing pulses from interval patterns before pairing.One missing pulse shifts all subsequent order-based pairs.
Clock modelFunction mapping behavior time to ephys time.offset + slope × timeStart linear; use segmented or nonlinear models only for curved residuals or clock jumps.An overly complex model fits pulse jitter; an overly simple model leaves systematic drift.
Residual toleranceMaximum allowed timing error after alignment.Report the observed value without hiding itSet from task timescale and device precision; millisecond spike responses require tighter limits.Loose tolerance retains mismatches; strict tolerance rejects normal TTL jitter.
Shared-clock assumptionWhether behavior seconds are treated directly as ephys seconds without TTLs.Enabled with a warning only when TTLs are absentUse only with a shared hardware clock or externally completed synchronization.Cannot detect offset or drift; the limitation must appear in the report.

07 Behavior quality precedes neural interpretation

ParameterMeaningDefaultRecommendationEffect of changing it
Condition columnTrial field used for group comparisons.conditionUse original task labels and maintain a data dictionary.Recoding changes groups and counts; preserve the mapping.
Reaction-time start/endTwo events defining reaction time.stimulus_onset → responseDefine from the scientific question; movement onset, button press, and reward are not interchangeable.Different endpoints change both values and neural interpretation.
Minimum trialsMinimum valid trials required for a condition.Warning only; no automatic exclusionUse power analysis based on effect, variance, and validation design rather than one universal count.Higher thresholds improve stability but exclude more sessions.
Outlier ruleRule defining outliers in reaction time or continuous behavior.No deletion by defaultPrefer task-defined limits or robust rules and report excluded counts.Post-hoc limits can change condition effects and introduce bias.

08 Neural activity analysis workbench

ParameterMeaningDefaultRecommendationEffect of changing it
Alignment eventTime zero for every trial.stimulus_onset (depends on the event table)Choose from the hypothesis; stimulus, movement, choice, and reward answer different questions.Changing the event changes temporal interpretation and must not be significance-driven.
WindowTime range extracted around the event.-1 to +2 sCover baseline and expected response while avoiding neighboring trials or events.Short windows miss slow responses; long windows increase overlap and multiplicity.
Bin sizeTemporal bin width for PSTH or count features.50 msUse 5–20 ms for fast sensory responses and 20–100 ms for behavioral/population trends, with sensitivity checks.Small bins improve resolution but are noisy; large bins smooth responses and lower peaks.
SmoothingKernel and width applied to binned firing rates.Minimal or offSmoothing is acceptable for display; statistics should prefer unsmoothed trial features and report the kernel.Stronger smoothing lowers peaks, broadens responses, and induces temporal dependence.
PSD methodPower-spectral estimator and segmentation settings.WelchStart with Welch for stationary segments and report window, overlap, resolution, and units.Long windows improve frequency resolution but reduce temporal localization, and vice versa.
SurrogatesNumber of time shifts or label shuffles used for a chance distribution.200 (demonstration)Use at least 1,000 for formal analysis and more for tail p-values; fix the random seed.Fewer runs are faster but give coarse p-values; more runs are stable but expensive.

09 From figures to statistical evidence

ParameterMeaningDefaultRecommendationEffect of changing it
Sampling unitIndependent observational unit used for inference.Must be confirmed by the userAnimal-level claims usually require animals as independent units, with units/sessions nested.Too fine inflates n and significance; too coarse loses information.
PairedWhether conditions come from the same or matched observational unit.Defined by the study designUse paired tests for repeated observations from the same unit/session/animal.Incorrect pairing changes the error term and statistical power.
AlphaPredefined type-I error threshold.0.05Set before analysis and report together with multiplicity correction.Lower alpha is conservative but increases misses; never change it post hoc for significance.
Multiple comparisonMethod controlling error across a family of tests.FDR Benjamini–HochbergUse FDR for exploratory multi-unit/time tests and Holm for a few planned comparisons; define the family.Stricter correction reduces false positives and power; correction is meaningless without a defined family.
ResamplesNumber of permutation or bootstrap repetitions.1,000Use 200–1,000 for preview and often 5,000–10,000 for final estimates with a fixed seed.Controls Monte Carlo stability of p-values/intervals and runtime.

10 Machine learning, clustering, and leakage

ParameterMeaningDefaultRecommendationEffect of changing it
Feature windowTime range used to extract neural features for each trial.0–0.5 s (task-dependent)Predefine from causal timing; do not use post-behavior information to predict behavior.Long windows contain more information but can include later events and movement.
Cross-validationTrain/validation split and repetition scheme.5-fold stratified or groupedUse GroupKFold or LeaveOneGroupOut when sessions or animals must not cross folds.Random trial splits often score higher but may learn session identity.
ScalingFeature standardization or normalization.StandardScaler for linear/SVM modelsFit within every training fold and apply to its validation fold.Scaling the full dataset first leaks validation means and variances.
Class weightingLoss weights for imbalanced classes.balanced (for imbalanced classes)Report class counts first; weighting or resampling must occur inside training folds.Changes decision boundaries and calibration; ordinary accuracy is insufficient.
Permutation countNumber of label shuffles with complete re-validation.200 (demonstration)Use at least 1,000 for final results while preserving group structure.One shuffle is unstable; invalid shuffling destroys nesting.

11 Publication figures and reproducible export

ParameterMeaningDefaultRecommendationEffect of changing it
FormatFigure file type.PNG + SVGUse PNG for preview and SVG/PDF for vector editing and publication.Raster output depends on DPI; vector output preserves line and text objects.
Figure sizeOutput width and height.Use the current figureSet journal single/double-column dimensions in millimeters and inspect long labels.Changing dimensions alters relative text size and panel spacing.
DPIPixels per inch for raster output.300Use 300–600 DPI for line art and follow journal/source resolution for images or heatmaps.Higher DPI increases file size but cannot add source-data resolution.
Axis/grid/spineAxis line width, extent, ticks, grid, and spine visibility.NeuroFlow standard themeAdjust by plot type and keep a figure consistent; do not let decorative grids obscure data.Thick lines improve visibility but crowd small panels; strong grids compete with data.
Project source modeWhether the project uses an external read-only link or an internal raw copy.Defined by the import choiceBefore archiving, verify external paths; copy raw data or use stable shared storage for portability.The manifest remains readable, but raw-dependent stages cannot rerun if an external source is missing.
