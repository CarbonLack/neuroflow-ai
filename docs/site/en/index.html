NeuroFlow operation manual

A visible, replaceable, and restorable electrophysiology workflow

NeuroFlow connects raw multichannel recordings, replaceable spike sorters, behavior, neural analyses, statistics, machine learning, and publication export in one local-first project.

Product principles

Visible

Every stage exposes input, parameters, method, evidence, and limitations.

Replaceable

Sorters and stage outputs can be changed without hiding native files.

Restorable

The project manifest restores sources, completed stages, results, and audit history.

Start in five minutes

  1. Create an empty project and import your own data, or open a teaching simulation.
  2. Verify data structure and raw traces before preprocessing.
  3. Run each selected analysis from the fixed bottom action bar.
  4. Inspect figures, tables, parameters, and the audit log after every run.
  5. Save the project and reopen neuroflow_project.json to resume.
AI is optional. Manual and guided workflows remain fully usable without a local model.

The complete workflow

01

Start with the data structure

This page does more than select a file. NeuroFlow must know how each sample is stored, how many values form one time point, how probe contacts are arranged, and which device clock timestamps behavior. Those facts give filtering, sorting, and event alignment their correct physical units. Import keeps the source read-only and stores only links, caches, and derived results in the project.

Recommended first action： Create a project first, then choose the entry that matches the files you actually have.

Then： After confirming structure, continue to Raw QC; processed spikes begin at Unit QC.

02

Raw-signal quality control

QC does not automatically delete channels. It builds evidence about where an anomaly occurs in channel, time, and frequency and whether it can affect referencing or spike detection. Locate problems globally, verify them in zoomed traces, and only then label candidate bad channels.

Recommended first action： Run summary and timeline first, then verify every candidate in traces and spectra.

Then： Carry confirmed bad channels and artifact intervals into separate AP and LFP preprocessing branches.

03

Preprocessing is not a fixed recipe

More preprocessing is not automatically better. Every operation changes the signal, so its purpose, order, and duplication inside the sorter must be explicit. NeuroFlow previews a short segment first and compares traces and spectra before parameters are committed to the workflow.

Recommended first action： Create separate AP and LFP branches rather than reusing one recipe.

Then： Send the AP branch to Spike sorting and retain the LFP branch for neural analyses.

04

Spike sorting and tool selection

Spike sorting assigns candidate events in multichannel voltage to units. NeuroFlow preserves each sorter's native files, parameters, and logs while normalizing shared outputs into units, spike times in seconds, and channel/template descriptions for downstream comparison.

Recommended first action： Run a representative segment with defaults to validate input and resources before the full session.

Then： Select an active sorting result and continue to Unit QC; return here when sorter comparison is needed.

05

Unit QC and manual review

Sorter output contains candidate clusters. Unit QC combines firing rate, refractory-period evidence, SNR, waveforms, amplitude over time, and ACGs so the researcher can assign traceable keep, MUA, noise, or uncertain labels. No single threshold replaces review.

Recommended first action： Inspect population distributions first, then review boundary and high-impact units.

Then： After selecting downstream units, import behavior and TTL data and establish a common timeline.

06

TTL, behavior, and a common timeline

Behavior computers, cameras, and electrophysiology systems often have independent clocks. The synchronization page fits offset + slope × behavior_time from paired TTL pulses and uses residuals to detect missing pulses, mismatches, or nonlinear drift. Without matching TTLs, NeuroFlow can only assume a shared clock and labels that assumption explicitly.

Recommended first action： Inspect event/TTL counts and intervals before fitting.

Then： Use the synchronized trial table to inspect behavior before event-aligned neural analysis.

07

Behavior quality precedes neural interpretation

Behavior analysis first asks whether the experiment ran as designed: trial counts per condition, choice balance, reaction times, missing values, and exclusions. Neural responses and machine-learning labels become interpretable only after behavior structure is reliable.

Recommended first action： Generate and save behavior figures before neural figures.

Then： After locking valid trials and condition labels, continue to event response, spike-train, LFP, or joint analyses.

08

Neural activity analysis workbench

The neural page is not a single fixed PSTH. It contains independently runnable event-response, spike-train, LFP spectral/time-frequency, and spike-field coupling analyses. Every sub-analysis has its own inputs, settings, figures, and tables; before execution it shows an input preview, never fabricated results.

Recommended first action： Run one clearly defined sub-analysis at a time and review its input/settings summary first.

Then： Send trial-level neural metrics to Statistics or build a trial-by-feature matrix for Machine Learning.

09

From figures to statistical evidence

Statistics begins with the sampling unit, not a test name. Trials are nested in sessions and units in animals; pairing, repeated measures, and hierarchy determine valid comparisons. The page reports effects, confidence intervals, and multiplicity handling rather than treating p-values as the only result.

Recommended first action： Create a statistical-design card before enabling test selection.

Then： Statistical results can go to publication export; prediction questions continue to Machine Learning.

10

Machine learning, clustering, and leakage

Machine Learning converts neural activity to a trial-by-feature matrix and places preprocessing, feature selection, and the model inside cross-validation. The goal is not the highest score but a leakage-free evaluation against a shuffle baseline with session/animal generalization.

Recommended first action： Establish a linear baseline before comparing complex models.

Then： Send model configuration, validation splits, score tables, and figures to Publication and Reproducibility.

11

Publication figures and reproducible export

Export binds figures to plotted data, statistical tables, Methods, the software environment, and the workflow. Visual edits never rewrite analysis data; recomputation and styling have separate audit trails. A saved neuroflow_project.json restores completed stages and the active result.

Recommended first action： Save vector output, plotted data, statistical tables, and generation settings for every publication figure.

Then： After the reproducibility bundle, the researcher remains responsible for interpretation, manuscript structure, and data-sharing decisions.
